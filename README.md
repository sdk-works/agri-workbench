# 青禾 · 农业 AI 工作台 v0.4

员工正常问答、轻量反馈 → 后台独立裁判与规则分流 → 领域专家确认 → 审核数据集。

v0.4 已包含：农业结构化标注与审核（AI 建议标签、专家确认）、入库拦截规则（管理员配置，命中拦截/提示）、图片提问（随问题把图片发给视觉模型）、单份 MD/JSON 下载、可追溯 ZIP 资产包、批量导入、资料生成候选问答、数据集预检、训练任务草稿。接口用法见 [资产接口说明](ASSET-API.md) 与 [接口契约](API-CONTRACT.md)。

训练执行器、OCR 和模型部署未接入。训练任务可以绑定已审核数据快照、查询和取消，但不能执行训练。知识 MD/JSON 用于保存与检索，不能直接等同于已经适配模型模板的训练数据。

检查命令：`npm test`（功能及回归）、`npm run test:smoke`（隔离数据库下的真实 HTTP 主流程）、`npm run build`。测试不会调用真实云端模型，详见 [验证记录](VERIFICATION.md)。

## 启动与首次登录

需要 Node.js 24+、npm；本地推理需 Ollama。前后端仍运行在你自己的电脑或服务器。

```bash
npm ci
npm run server
npm run dev -- --port 5174 --strictPort
```

首次把 `server/.env.example` 复制为 `server/.env`，已有文件不要覆盖。打开 http://127.0.0.1:5174/ ，创建管理员账号（账号 3–60 位，密码至少 10 位），然后在「员工管理」创建普通员工、领域专家。无需每次填写姓名，显示名可为昵称或工号。没有内置通用密码。

后端只监听本机 8787。生产前端可由反向代理提供 dist 静态文件并代理 /api；原有静态 Dockerfile **不包含后端或数据库**。公开部署需 HTTPS、明确的 ALLOWED_ORIGINS 和 COOKIE_SECURE=true。本期按单个服务进程、单企业园区运行，尚未实现多实例任务租约或商业多租户开通流程。

## 使用流程

- 普通员工：正常提问，选择采用 A/B、都可以、都不好或信息不足；反馈可选，不影响继续问答。只能看自己的会话。可上传资料。
- 连续追问：上下文采用员工所选回答；未选择时优先本地有效回答，再使用云端有效回答。每轮只使用一个答案，保存真实上下文；修改反馈不改写已生成历史。保留最近 10 轮，超长时提示新建会话。
- 领域专家：查看被分配领域的评审和待审资料。可确认原答、局部修订、补充依据或排除。常规案例可单人确认，关键操作或冲突需另一名领域专家复审。修订版本永久保留。被拦截资料发布/退回时需确认已人工核实，处理后拦截标记清除。
- 管理员：账号授权、模型配置、分流规则、入库拦截规则、异常任务重试、数据集导出与旧版数据读取。管理员权限不替代独立复审要求。

## 图片提问

提问框可附一张图片（PNG/JPG/WEBP/GIF，≤8 MB），随问题一起发给模型看图回答。本地 Ollama 走 images 数组、兼容接口走 image_url，需要视觉模型（本地如带 mmproj 投影的千问模型，云端如 glm-4v 系列）；文本模型会忽略或答非所问。图片 base64 只随当前轮传给模型，不进入历史上下文，也不出现在列表接口返回中；当前导出数据集不含图片问题样本。

## 入库拦截规则

管理员在「模型与规则 → 入库拦截规则」配置规则：关键词（空格或逗号分隔）或正则，动作分「拦截」与「提示」。资料上传清洗完成后自动匹配——命中拦截的文档进入 blocked 状态不能发布，命中提示的文档保持待审核但带标记；列表和详情返回命中规则与命中片段。被拦截资料由领域专家人工核实后发布或退回（需确认），处理记录随版本留存。未配置规则时资料不触发拦截。正则编译失败或长度超限会直接拒绝保存。

## 本地回答、云端回答、裁判

「模型与规则」中分别配置三个角色，以及可选的本地备用裁判。默认本地千问 qwen2.5:7b，云端沿用智谱 glm-4.7-flash 与已有 ZHIPU_API_KEY。裁判默认待配置，旧 JUDGE_MODEL 不会自动复用。

兼容 API 支持配置基础地址、模型、独立密钥（Chat Completions 格式）。基础地址不含 `/chat/completions`。Ollama 使用 `/api/chat`。模型密钥在服务器 `data/model-config.json` 保存，接口只返回是否已配置；浏览器输入的新密钥保存后清空。配置成功不代表供应商实际可调用。

裁判在双回答完成后自动运行，不等待反馈，也不读员工投票。结构化输出评分、实质差异、冲突、缺失条件、证据状态。限流/超时等有限重试；最终失败明确记录，可手动重试。本地备用默认关闭，开启后结果标记为降级，重合模型记录自评风险。裁判意见不会自动审核数据或训练模型。

可填写输入/输出每百万 token 的人民币单价；仅估算已记录的成功调用，未涵盖失败重试或供应商附加收费。以实际账单为准。

## 自动分流

实质差异、事实或操作冲突、依据不足、两者都差、员工负面反馈、关键操作、人机实质判断不一致进入评审。仅措辞不同不直接送审。普通样本默认抽查 5%，每日普通新任务预算 30，管理员可调整。超额普通案例保留待分配；关键案例不受该预算限制。

相同问题、领域和上下文的未结束案例合并，保留每次回答；审核只发布主案例，不能把其他答案视为同时合格。字符相似度不用于代替事实判断。供应商异常进入运行任务，不因 429 占用农业专家队列。

抽样按问题哈希稳定决定，并非严格随机独立样本。关键操作检测目前为规则关键词，不能保证识别全部农业风险。应根据抽查结果和专家结论调整规则。

## 资料清洗与知识检索

支持 TXT/MD、CSV、JSONL、DOCX、文字 PDF、XLSX，单个 8 MB；扫描 PDF 需先 OCR。解析在限时、限堆内存工作线程中完成；最多 300 PDF 页、20,000 片段、150 万字符。不要上传宏文件或旧版 .doc/.xls。

保存原文件及 SHA-256，保留页码/段落/记录行/工作表行位置。清理控制符、零宽字符和空片段，标记重复片段但不擅自删除表格重复值；识别常见手机号、邮箱、身份证号。人名、客户信息和商业机密仍需人工检查。同人同领域相同文件不重复入库，近似资料给专家提示。

专家确认来源、适用范围、敏感信息后，发布审核文本版本。只有已发布文本参与本领域检索；当前为轻量关键词片段召回，不是向量检索。调用记录保存实际引用片段和资料版本。上传资料不会直接训练。专家可从资料发起候选案例，自动送入评审。

## 数据、备份和 PostgreSQL

- 新版默认 `data/workspace.sqlite`（WAL、FULL 同步、事务写入），原始资料在 `uploads/`。
- 用户、会话、问答轮、反馈、后台任务、专家任务、资料、修订版本、导出和审计各自独立表；内部账号 ID 关联操作。会话令牌只存哈希，密码使用 scrypt。
- 原 `data/workbench.sqlite` 保留不变，管理员可在「模型与规则」读取/导出旧记录；旧记录没有可信登录身份，不自动指派给新员工，不自动重发模型调用。
- 正式多人部署可设置 DATABASE_URL 使用 PostgreSQL。`compose.postgres.yml` 提供 PostgreSQL 17 的单机服务模板，需要自行设置 POSTGRES_PASSWORD。这不是主从高可用部署。

SQLite 完整备份到一个尚不存在的目录：

```bash
npm run backup -- backups/2026-10-09
```

备份包含数据库、原始资料和已保存模型配置；保护其中业务数据和密钥。还应独立安全备份 server/.env。恢复时停止服务，使用全新数据目录恢复，避免与旧 WAL 混用。旧版专用备份命令为 `npm run backup:legacy -- backups/legacy.sqlite`。

SQLite → PostgreSQL：先停止写入、做备份，保持 WORKSPACE_DATA_PATH 指向源文件，设置目标 DATABASE_URL 后：

```bash
npm run migrate:postgres
```

目标表必须为空；单事务迁移并核对数量和内容，不迁移登录会话，不删除源库。上传目录和模型配置保持原路径或单独复制。成功后启动服务会使用 PostgreSQL。PostgreSQL 备份使用 pg_dump，并保留原始文件目录和模型配置。

目前查询与统计仍适合内部试用量级；大规模采集应独立建设时序数据通道，不把每条传感器读数写入问答表。多实例、高并发、长期负载、DGX ARM64 部署仍需专项验收。

## 训练数据

使用记录、送审候选、审核数据分开。只有专家确认才能导出 SFT/DPO/eval；DPO 要确认原始优选回答合格，专家修订与原始答案分开保存。训练/评测按会话固定，并在导出时对相同问题及重叠资料来源做保守隔离。语义改写的无来源案例仍需正式训练前专项去重。导出形成不可变版本快照并脱敏常见个人标识。

本项目不自动微调、不自动替换线上模型、不向风机/阀门发送控制指令。Langfuse 等外部评估平台尚未接入；现有内部记录提供后续映射基础。
