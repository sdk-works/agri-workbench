# 京阳智农 · 农业 AI 工作台 v0.4

员工正常问答、轻量反馈 → 后台独立裁判与规则分流 → 领域专家确认 → 审核数据集。

生产上跑三个进程：网关直出前端产物（:8080），API 走后端（:8787），公网 HTTPS 由 `deploy/https-proxy.mjs` 终结（云服务器只做端口转发）。手机端另有一个 WebView 壳（`android/`），只负责加载服务端页面——**改业务、改界面都不用发 APK**。

## 本地开发

需要 Node.js 24+、npm；本地推理需 Ollama。前后端仍运行在你自己的电脑或服务器。

```bash
npm ci
npm run server
npm run dev -- --port 5174 --strictPort
```

首次把 `server/.env.example` 复制为 `server/.env`，已有文件不要覆盖。打开 http://127.0.0.1:5174/ ，创建管理员账号（账号 3–60 位，密码至少 10 位），然后在「员工管理」创建普通员工、领域专家。无需每次填写姓名，显示名可为昵称或工号。没有内置通用密码。

公开部署需 HTTPS、明确的 ALLOWED_ORIGINS 和 COOKIE_SECURE=true。本期按单个服务进程、单企业园区运行，尚未实现多实例任务租约或商业多租户开通流程。

## 使用流程

- 普通员工：正常提问，选择采用 A/B、都可以、都不好或信息不足；反馈可选，不影响继续问答。只能看自己的会话。可上传资料。
- 连续追问：上下文采用员工所选回答；未选择时优先本地有效回答，再使用云端有效回答。每轮只使用一个答案，保存真实上下文；修改反馈不改写已生成历史。保留最近 10 轮，超长时提示新建会话。
- 领域专家：查看被分配领域的评审和待审资料。可确认原答、局部修订、补充依据或排除。常规案例可单人确认，关键操作或冲突需另一名领域专家复审。修订版本永久保留。被拦截资料发布/退回时需确认已人工核实，处理后拦截标记清除。
- 管理员：账号授权、模型配置、分流规则、入库拦截规则、异常任务重试、数据集导出与旧版数据读取。管理员权限不替代独立复审要求。

## 图片提问

提问框可附一张图片（PNG/JPG/WEBP/GIF，≤8 MB），随问题一起发给模型看图回答。本地 Ollama 走 images 数组、兼容接口走 image_url，需要视觉模型（本地如带 mmproj 投影的千问模型，云端如 glm-4v 系列）；文本模型会忽略或答非所问。图片 base64 只随当前轮传给模型，不进入历史上下文，也不出现在列表接口返回中；当前导出数据集不含图片问题样本。

## 入库拦截规则

管理员在「模型与规则 → 入库拦截规则」配置规则：关键词（空格或逗号分隔）或正则，动作分「拦截」与「提示」。资料上传清洗完成后自动匹配——命中拦截的文档进入 blocked 状态不能发布，命中提示的文档保持待审核但带标记；列表和详情返回命中规则与命中片段。被拦截资料由领域专家人工核实后发布或退回（需确认），处理记录随版本留存。未配置规则时资料不触发拦截。正则编译失败或长度超限会直接拒绝保存。

## 本地回答、云端回答、裁判

「模型与规则」中分别配置三个角色，以及可选的本地备用裁判。默认本地千问 qwen2.5:7b，云端沿用智谱 glm-4.7-flash 与已有 ZHIPU_API_KEY。裁判默认待配置，旧 JUDGE_MODEL 不会自动复用。

兼容 API 支持配置基础地址、模型、独立密钥（Chat Completions 格式）。基础地址不含 `/chat/completions`。Ollama 使用 `/api/chat`。模型密钥在服务器 `data/model-config.json` 保存，接口只返回是否已配置；浏览器输入的新密钥保存后清空。配置成功不代表供应商实际可调用。

裁判在双回答完成后自动运行，不等待反馈，也不读员工投票。结构化输出评分、实质差异、冲突、缺失条件、证据状态。限流/超时等有限重试；最终失败明确记录，可手动重试。本地备用默认关闭，开启后结果标记为降级，重合模型记录自评风险。裁判意见不会自动审核数据或训练模型。

可填写输入/输出每百万 token 的人民币单价；仅估算已记录的成功调用，未涵盖失败重试或供应商附加收费。以实际账单为准。

## 自动分流

实质差异、事实或操作冲突、依据不足、两者都差、员工负面反馈、关键操作、人机实质判断不一致进入评审。仅措辞不同不直接送审。普通样本默认抽查 5%，每日普通新任务预算 30，管理员可调整。超额普通案例保留待分配；关键案例不受该预算限制。

相同问题、领域和上下文的未结束案例合并，保留每次回答；审核只发布主案例，不能把其他答案视为同时合格。字符相似度不用于代替事实判断。供应商异常进入运行任务，不因 429 占用农业专家队列。

抽样按问题哈希稳定决定，并非严格随机独立样本。关键操作检测目前为规则关键词，不能保证识别全部农业风险。应根据抽查结果和专家结论调整规则。

## 资料清洗与知识检索

支持 TXT/MD、CSV、JSONL、DOCX、文字 PDF、XLSX，单个 8 MB；扫描 PDF 需先 OCR。解析在限时、限堆内存工作线程中完成；最多 300 PDF 页、20,000 片段、150 万字符。不要上传宏文件或旧版 .doc/.xls。

保存原文件及 SHA-256，保留页码/段落/记录行/工作表行位置。清理控制符、零宽字符和空片段，标记重复片段但不擅自删除表格重复值；识别常见手机号、邮箱、身份证号。人名、客户信息和商业机密仍需人工检查。同人同领域相同文件不重复入库，近似资料给专家提示。

专家确认来源、适用范围、敏感信息后，发布审核文本版本。只有已发布文本参与本领域检索；当前为轻量关键词片段召回，不是向量检索。调用记录保存实际引用片段和资料版本。上传资料不会直接训练。专家可从资料发起候选案例，自动送入评审。

## 数据、备份和 PostgreSQL

- 新版默认 `data/workspace.sqlite`（WAL、FULL 同步、事务写入），原始资料在 `uploads/`。
- 用户、会话、问答轮、反馈、后台任务、专家任务、资料、修订版本、导出和审计各自独立表；内部账号 ID 关联操作。会话令牌只存哈希，密码使用 scrypt。
- 原 `data/workbench.sqlite` 保留不变，管理员可在「模型与规则」读取/导出旧记录；旧记录没有可信登录身份，不自动指派给新员工，不自动重发模型调用。
- 正式多人部署可设置 DATABASE_URL 使用 PostgreSQL。`compose.postgres.yml` 提供 PostgreSQL 17 的单机服务模板，需要自行设置 POSTGRES_PASSWORD。这不是主从高可用部署。

SQLite 完整备份到一个尚不存在的目录：

```bash
npm run backup -- backups/2026-10-09
```

备份包含数据库、原始资料和已保存模型配置；保护其中业务数据和密钥。还应独立安全备份 server/.env。恢复时停止服务，使用全新数据目录恢复，避免与旧 WAL 混用。旧版专用备份命令为 `npm run backup:legacy -- backups/legacy.sqlite`。

SQLite → PostgreSQL：先停止写入、做备份，保持 WORKSPACE_DATA_PATH 指向源文件，设置目标 DATABASE_URL 后：

```bash
npm run migrate:postgres
```

目标表必须为空；单事务迁移并核对数量和内容，不迁移登录会话，不删除源库。上传目录和模型配置保持原路径或单独复制。成功后启动服务会使用 PostgreSQL。PostgreSQL 备份使用 pg_dump，并保留原始文件目录和模型配置。

目前查询与统计仍适合内部试用量级；大规模采集应独立建设时序数据通道，不把每条传感器读数写入问答表。多实例、高并发、长期负载、DGX ARM64 部署仍需专项验收。

## 训练数据

使用记录、送审候选、审核数据分开。只有专家确认才能导出 SFT/DPO/eval；DPO 要确认原始优选回答合格，专家修订与原始答案分开保存。训练/评测按会话固定，并在导出时对相同问题及重叠资料来源做保守隔离。语义改写的无来源案例仍需正式训练前专项去重。导出形成不可变版本快照并脱敏常见个人标识。

本项目不自动微调、不自动替换线上模型、不向风机/阀门发送控制指令。Langfuse 等外部评估平台尚未接入；现有内部记录提供后续映射基础。

## 生产部署（当前实际跑法）

| 进程 | systemd 服务 | 监听 | 作用 |
|---|---|---|---|
| 后端 | `agri-workbench` | `127.0.0.1:8787` | `server/server.mjs`，全部业务与 API |
| 网关 | `agri-web` | `0.0.0.0:8080` | `deploy/gateway.mjs`，直出 `app/dist` 静态资源，`/api/*` 反代到 8787 |
| HTTPS | `agri-https` | `0.0.0.0:8544`（frpc 回源，PROXY v2）/ `127.0.0.1:8543`（局域网直连） | `deploy/https-proxy.mjs` 终止 TLS |

公网链路：`云服务器 443（frps）` → frpc → `本地 8544` → `网关 8080` → `后端 8787`。云服务器只做端口转发，不放业务数据、不跑模型。手机在没有安装根证书的环境下可退回明文 `http://<公网IP>:8080`：功能可用，但浏览器只在安全上下文给麦克风，语音录入不可用。

重启范围要分清：换前端产物**不用**重启后端；改 `server/*.mjs` 必须重启 `agri-workbench`；改 `deploy/gateway.mjs` 要重启 `agri-web`。

`app/public/` 下的 `ca.html`、`compat.html`、`diag.html`、`jingyang-ca.crt` 会被 vite 自动带进产物。手写产物目录或从别处整包拷 `dist` 时容易漏，漏了证书下载页就 404。

## 网关与前端发布

`deploy/gateway.mjs` 做三件事：直出 `app/dist`、把 `/api/*` 反代到后端、对页面路由回退 `index.html`。

- `index.html` 返回 `Cache-Control: no-cache`，每次打开都回源校验，所以换产物后用户刷新即生效。
- `assets/*` 文件名带内容哈希，可缓存 1 小时；产物一换文件名就变，不会读到旧代码。
- **`/assets/*` 和带扩展名的路径不存在时返回 404**，只有无扩展名的页面路由才回退 `index.html`。这条是实现细节但很关键：早期版本对缺失资源也返 200 + HTML，配合 `nosniff` 浏览器会拒绝执行，页面直接白屏，而且这个 HTML 还会被当成 JS 缓存 1 小时，表现成「怎么刷都白」。

发布前端：

```bash
npm run build                       # 产物落 app/dist
```

要保留旧产物回滚，替换前先 `cp -a app/dist backups/dist-<时间戳>`，出问题再换回来并重启 `agri-web`。

## 请求可恢复性

网络抖动、代理抖动、手机切网都不该让用户面对一句「发送失败」然后不知道该不该重发。前端按下面几条处理：

- **启动探测独立超时**：加载页面时的连通性探测 15 秒，失败直接显示「连不上工作台 + 重试连接」，不会白屏干等。
- **发送进待确认态**：提交超时或断网时，不直接报错，也不立刻重发，而是保留同一个 `request_id` 进「正在确认」。先只读回查 `GET /turns/{id}`——查到就认，确认没送到才用同一个 `request_id` 补发。服务端按 `request_id` 幂等，重复提交只会有一条轮次，不会重复生成、重复计费。
- **只读对账不建数据**：`GET /turns/{id}` 只查不改：不建轮次、不改状态、不调模型。
- **停止按钮不被忙等锁死**：原来整页共用一个 `busy`，请求卡住时恰恰点不了停止。现在只禁用被点的那一轮，文案区分「停止中…」「已停止本地等待」「服务端已确认停止」。取消是终态，重复取消回 `already_terminal`，迟到的完成结果不会把 `canceled` 覆盖回去。
- **切会话隔离迟到响应**：切换会话会递增 epoch，上一会话迟到的响应和新会话迟到的对账结论都会被丢弃，不会串到当前会话里。
- **后台轮询有节制**：上一发回来了才排下一拍，间隔按 3→6→12→24→30 秒退避；不再「一开始生成就全停」。
- `GET /turns?active=1` 不分会话列出在跑轮次，用于页面重开后找回后台任务。

## 语音

语音提问走同一套 API，前端录音后上传，识别与播报由 `voice_service.py` 提供。播报有三档预算：极简（说了太长→≤100 字/2 点）、简要（3 点/200 字）、详细（6 点/800 字）。

模型说跑偏时（比如让它列举原因，它从「第一」数到「第一百四十二」），服务端在流式过程中**在线拦截**：点数超预算或字数超上限即中止上游请求，按「截断完成」落库（`status=completed`、`ended_reason=trimmed`）。失败和取消路径也会截断，避免跑飞的原文整段留在库里、重开会话又被念一遍。

语音面板的附图是独立横条（可左右滑），不塞在字幕滚动区里——否则图一多就把「你说/回答」的文字顶出可视区。

## 热更新与版本边界

| 改动 | 是否要发 APK | 生效方式 |
|---|---|---|
| 前端界面、交互、样式 | 不用 | 换 `app/dist`，用户刷新即新版 |
| 后端逻辑、提示词、拦截规则 | 不用 | 重启 `agri-workbench` |
| 网关、证书、反代 | 不用 | 重启 `agri-web` / `agri-https` |
| WebView 内核参数、权限声明、原生能力（相机/蓝牙/后台） | **要发** | 重新打包 + 覆盖安装 |
| 首页地址、备用入口、证书信任列表、更新逻辑 | **要发** | 同上 |

设计原则：**版本检查放在前端 JS，不要放在 Java 的 `onResume` 里**，否则想改检查策略（加灰度、改时机）又得发版。壳只负责「加载一个网址」。

覆盖安装的前提是签名一致。签名密钥必须放在构建目录之外，否则每次构建清目录都会生成新密钥，新包和线上签名对不上，用户只能卸载重装（本地会话与未同步数据会一起丢）。

## 常见故障对照

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 手机白屏，页面标题能出来 | 200KB 级 JS 下载失败或被拦 | 换直连入口；清一次缓存；确认没走 VPN/代理 |
| 白屏且「怎么刷都一样」 | 缺失资源被当成 JS 缓存过 | 确认网关对 `/assets/*` 返回 404 而不是 200 HTML |
| 打开提示「连不上工作台」 | 启动探测 15 秒内没拿到响应 | 后端是否在跑、网关反代是否通 |
| HTTPS 打不开但 HTTP 能开 | 自签证书未被信任 | 装一次根证书（`/jingyang-ca.crt`），或用 APK（已内嵌 CA） |
| APK 打开白屏、提示无法连接 | 壳里 `HOME_URL` 是内网地址 | 换公网地址的包 |
| 语音录入用不了，但打字正常 | 页面不在安全上下文（明文 HTTP） | 走 HTTPS 或装根证书 |
| 聊天到一半突然「模型连接失败」 | 云端出口代理节点不可用 | 看 `data/` 日志；代理节点需自动探测切换 |

## 仓库结构

```
app/          前端 Vue 源码（src）、后端 Node 服务（server）、构建产物（dist）
deploy/       网关（gateway.mjs 静态直出与反代）、HTTPS 反代、证书（私钥不入库）
android/      APK 壳工程（WebView + 静默更新），含手写构建脚本 build.sh
docs/         架构、移动端接入、语音交互等专题文档
voice_service.py  本地语音服务（ASR/TTS）
```

## 安卓端（APK）

`android/` 是 WebView 壳，只负责加载 `https://<服务器>/`，业务界面全部由服务端前端产物提供。
所以**改业务、改界面都不用发 APK**，只有改壳内代码（首页地址、权限、证书信任、更新逻辑）才需要重新打包。

构建不用 Gradle，走 `android/build.sh`（aapt2 → javac → d8 → zipalign → apksigner）：

```bash
export KS_PASS=<签名口令>          # 口令不入库，密钥在服务器 ~/agri-keystore/qinghe.jks
bash android/build.sh              # 产物 ~/android-build/out/jingyang-<版本>.apk
```

依赖：Android SDK build-tools 34.0.0、platforms/android-34、JDK、python3。

发布时把 APK 放到网站目录，并同步更新升级描述 `agri-android.json`（versionCode / apkUrl / md5 / force）：
客户端启动时拉该文件比对 versionCode，有新版即后台下载并拉起安装界面。

壳内要点：
- `HOME_URL` 必须是公网地址，写内网地址会在外网白屏
- `FALLBACK_URL` 也要是公网地址，否则主入口失败后切到备用入口仍然连不上
- `res/raw/jingyang_ca.crt` 内嵌私有 CA，配合 `network_security_config.xml` 只对指定域名额外信任，
  不用「忽略所有 SSL 错误」这种写法
- 签名密钥必须放在构建目录之外，否则每次构建清目录会生成新密钥，覆盖安装失败

## 近期更新（2026-10-27 ~ 10-29）

- **云端回答连不上**：Node 内置 fetch 的连接超时固定 10 秒，而经代理到 OpenAI 的握手动辄 11 秒以上，必然超时；改用 undici `ProxyAgent` 后可正常连接。之后又出现「第二天又失败」，真因是代理节点漂移，已加 5 分钟自动探测与切换。
